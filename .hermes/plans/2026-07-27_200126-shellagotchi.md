# Shellagotchi Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Build `shellagotchi` — a Linux userland daemon + CLI that keeps a virtual "terminal pet" alive, fed by the exit codes of the user's shell commands, with ASCII-art visualisation, a shell-prompt segment, sleep/boredom/poop lifecycle mechanics, and cleanup via a `clean` command.

**Architecture:** A single Rust binary with three modes: (1) a long-lived `daemon` managed by a **systemd user unit** that owns the pet's state, ticks the simulation, and persists to disk; (2) a **shell hook** (`bash`/`zsh`/`fish`) that after every command fires a fire-and-forget event (exit code + duration + command basename) to the daemon over a **Unix domain socket**; (3) a **CLI/TUI client** (`status`, `show`, `watch`, `clean`, `pet`, `feed`, `prompt`) that queries the same socket. The prompt segment never touches the socket in the hot path — the daemon atomically writes a tiny pre-rendered cache file that the prompt just `cat`s, keeping prompt latency < 1 ms.

**Tech Stack:** Rust 1.79+ (stable, 2021 edition), `tokio` (async runtime + UnixListener), `serde`/`serde_json` (IPC + state), `toml` (config), `clap` v4 (CLI, derive), `ratatui` + `crossterm` (live TUI), `chrono` (clock, night detection), `directories` (XDG paths), `tracing`/`tracing-subscriber` (logging to journald via stderr), `anyhow`/`thiserror` (errors). Testing: built-in `cargo test` + `assert_cmd`, `tempfile`, `mockall`-free hand-rolled clock injection.

**Why Rust over Go:** single static-ish binary, no GC pauses in a daemon that must stay tiny (<10 MB RSS), first-class `ratatui` for the ASCII view, and trivially fast startup for the CLI path (Go is also fine; if the implementer prefers Go, the same module boundaries map 1:1 onto packages — but do **not** mix, pick Rust as specified here).

## Domain Model

### Stats (all `u8`, clamped 0–100)

| Stat | Rises when | Falls when | Effect |
|---|---|---|---|
| `satiety` (fullness) | a command exits **0** (+2, capped) | time passes (−1 / 20 min awake) | 0 → health decay, mood `Starving` |
| `happiness` | success streaks, `pet` command, being clean | failures (−3 each), boredom, dirt, hunger | drives face sprite |
| `energy` | sleeping (+8/h) | awake time (−2/h), heavy activity | 0 → forced sleep |
| `hygiene` | `clean` command (→100) | each poop on the ground (−15), time (−1/h) | low → sickness risk |
| `boredom` | no commands for > `boredom_after` (default 45 min) | any command, `pet` | high → happiness decay |
| `health` | slowly regenerates when all stats > 50 | starving, filthy, exhausted | 0 → `Dead` (config: revive vs. permadeath) |
| `discipline` | resisting junk (see below) | — | v2, **YAGNI for now** |

### Derived

- `age_secs`, `commands_eaten`, `success_streak`, `failure_streak`, `poops: Vec<Poop>`, `last_seen`, `evolution_stage`.
- **Mood** = f(stats): `Ecstatic | Happy | Content | Meh | Sad | Miserable | Sick | Dead`.
- **Activity** = `Asleep | Awake | Playing | Eating | Pooping | Sick | Dead`.
- **Evolution stages** by age: `Egg` (0–10 min) → `Blob` (<1 day) → `Child` (<3 days) → `Teen` (<7 days) → `Adult` (7 d+); a stage-up requires average happiness over the period ≥ 50, else a "stunted" variant sprite. (Keep to 5 stages; no branching tree in v1.)
- **Species**: at `hatch`, one of `config.species_pool` (default `["blob", "cat", "dragon", "ghost"]`) is picked uniformly at random via the injected RNG (seeded in tests). Each species has its own sprite set for every `(stage, activity, mood)` combo — same stat mechanics across species, purely cosmetic in v1 (no stat bonuses/species traits, YAGNI). `--species <name>` on `hatch` overrides the random pick for users who want to force one.

### Feeding rules (the core mechanic) — "bad food" framing

Event payload from the hook: `{ exit_code, duration_ms, argv0, cwd_hash, ts }`.

- `exit_code == 0` → "good food": `satiety += 2`, `happiness += 1`, `success_streak += 1`, `failure_streak = 0`. Streak of 10 → bonus `happiness += 5` and a "hyper" animation frame.
- `exit_code != 0` → "bad food": still nutritious (`satiety += 3` — a bad meal fills the belly *more* than a good one, junk-food logic), but each bad meal adds to a `bad_food_meter` (decays slowly, −1/h) and rolls a **sickness check**: `p = min(0.5, 0.05 * bad_food_meter)` per event. On a sickness hit: `health -= 10`, mood forced toward `Sick` for the next tick, one-off `happiness -= 2` "queasy" reaction (distinct from the old flat per-failure happiness penalty — happiness is no longer directly docked by every failure, only by getting sick from eating too much bad food). `failure_streak` still increments for streak-based cosmetics (grumpy face threshold). `130` (SIGINT/Ctrl-C) and `148`, plus configurable `ignored_exit_codes = [130]`, are treated as **neutral** — no satiety, no bad_food_meter change, the user aborting is not the pet's fault.
- `argv0` in `config.junk_food` (default `["rm", "kill", "pkill", "dd"]`) → extra `bad_food_meter += 1` regardless of exit code ("spicy food" — always risky to eat).
- `argv0 == "clean"` (or any name in `config.clean_commands`, default `["clean", "shellagotchi-clean"]`) → hygiene → 100, all poops removed, `happiness += 5`. **Also**: `shellagotchi clean` does the same explicitly.
- Rate limit: max `config.max_feeds_per_min` (default 30) counted feeds/min, so `for i in {1..10000}; do true; done` can't gorge the pet into instant adulthood. Excess events are counted but give 0 nutrition.
- Commands issued while `Asleep` do **not** feed; they add `sleep_disturbance` (>5 in one night → −5 happiness, "grumpy" morning sprite).

### Life cycle timers (all configurable)

- **Sleep**: `sleep_start = 23:00`, `wake = 07:00` local. Also a nap if `energy == 0`. While asleep: satiety decay halves, energy +8/h, sprite = `zzz` frames.
- **Boredom**: no event for `boredom_after` (45 min) while awake → `boredom += 5` per 15 min; at `boredom > 70`, `happiness -= 2` per 15 min. `shellagotchi pet` / `play` resets boredom to 0 (cooldown 10 min so it can't be spammed).
- **Pooping**: purely commands-eaten driven — every `poop_interval_commands` (default 40 fed/counted commands, config key, no time component) a `Poop { at: DateTime }` is pushed. Each uncleaned poop: `hygiene -= 15` immediately and `happiness -= 1` per hour. ≥3 poops → `Sick` risk roll each tick (`p = 0.05 * poops` per hour), on top of the bad-food sickness roll — the two sources are independent and additive in probability space (capped at 0.9 combined).
- **Sickness**: `health -= 5/h` while sick (compounds with any bad-food sickness hit), mood forced `Sick`, cured by `clean` + 2 h of satiety > 60 + `bad_food_meter` back under threshold.
- **Death**: `health == 0` for a full tick → `Dead`. Config `on_death = "revive" | "grave" | "restart"`. Default `grave`: sprite becomes a tombstone, `shellagotchi hatch` starts a new pet (old one archived to `graveyard.jsonl`).

### Offline / catch-up semantics

On daemon start and after suspend/resume, compute `elapsed = now - state.last_tick` and replay ticks in **capped** chunks: `min(elapsed, config.max_offline = 12 h)` at coarse granularity (one virtual tick per 5 min of elapsed time, max 144 iterations). Night hours inside the gap are simulated as sleep. This prevents a laptop closed for a week from returning a dead pet by default (`max_offline` is user-tunable; set to `inf` for hardcore mode).

## IPC Protocol

Newline-delimited JSON over `SOCK_STREAM` Unix socket. One request → one response → close.

```jsonc
// Requests
{"v":1,"op":"feed","exit_code":0,"duration_ms":142,"argv0":"cargo","ts":1770000000}
{"v":1,"op":"status"}                 // -> full PetState snapshot
{"v":1,"op":"prompt","format":"compact"}
{"v":1,"op":"clean"}
{"v":1,"op":"pet"}
{"v":1,"op":"hatch","species":"blob"}
{"v":1,"op":"ping"}
```

```jsonc
// Responses
{"ok":true,"state":{ /* PetState */ }}
{"ok":true,"prompt":"🥚 ^_^ 82%"}
{"ok":false,"error":"pet is dead; run `shellagotchi hatch`"}
```

`feed` is fire-and-forget from the hook's perspective: the client writes and closes without reading, with a **100 ms** total budget and `SO_SNDTIMEO`; any error is swallowed. Version field `v` allows protocol evolution; unknown `op` → `{"ok":false,"error":"unsupported op"}`.

## Shell Integration

### Hook design (bash)

`shellagotchi init bash` prints:

```bash
# shellagotchi
__shellagotchi_report() {
  local ec=$?
  local d=$(( ${EPOCHREALTIME/./} / 1000 - ${__SHELLAGOTCHI_T0:-0} ))
  SHELLAGOTCHI_ARGV0="${__SHELLAGOTCHI_CMD%% *}" \
    shellagotchi feed --exit "$ec" --duration "$d" >/dev/null 2>&1 &
  disown 2>/dev/null
  return $ec        # CRITICAL: preserve $? for the user's own prompt
}
__shellagotchi_preexec() { __SHELLAGOTCHI_CMD="$BASH_COMMAND"; __SHELLAGOTCHI_T0=$(( ${EPOCHREALTIME/./} / 1000 )); }
trap '__shellagotchi_preexec' DEBUG
PROMPT_COMMAND="__shellagotchi_report;${PROMPT_COMMAND}"
PS1='$(shellagotchi prompt) '"$PS1"
```

Notes / pitfalls the implementer must respect:
- **Preserve `$?`** — the hook runs first and must not clobber the user's exit code. Verified by a dedicated test.
- Prefer forking the `feed` in background (`&`) but **only** if `config.async_feed` — a background job spams `[1]+ Done` in interactive bash; safer default is a synchronous call that self-limits to a 5 ms connect timeout. Benchmark both in Task 18.
- `PS1` uses `$(shellagotchi prompt)` which **only reads the cache file** — no socket, no JSON. Must be < 1 ms; enforce with a `hyperfine` check.
- zsh: use `precmd`/`preexec` hooks via `add-zsh-hook`; fish: `function __shellagotchi_postexec --on-event fish_postexec`.
- Provide `shellagotchi init --print-only` and a `doctor` subcommand that diagnoses: socket present? daemon alive? hook installed? prompt cache fresh? shell detected?

### Prompt formats

- `compact` (default): `<sprite-glyph> <face> <bar>` e.g. `🐣 ^_^ ▓▓▓▓░` (ASCII fallback `(^_^)` when `config.unicode = false` or `NO_COLOR`/dumb term).
- `minimal`: single mood glyph.
- `verbose`: `♥82 ☺91 ⚡40 ✦clean`.
- Cache file contains **all three** pre-rendered, newline-separated; `prompt` picks by flag/env. Cache is rewritten by the daemon on every state change and at least every 60 s; if the cache is older than `5 * tick_interval`, `prompt` prints a dimmed `?` (daemon down) rather than blocking.

## systemd unit

`systemd/shellagotchi.service` → installed to `~/.config/systemd/user/`:

```ini
[Unit]
Description=Shellagotchi terminal pet daemon
Documentation=man:shellagotchi(1)

[Service]
Type=notify
NotifyAccess=main
ExecStart=%h/.local/bin/shellagotchi daemon
Restart=on-failure
RestartSec=2
WatchdogSec=120
# hardening
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=read-only
ReadWritePaths=%h/.local/state/shellagotchi %h/.config/shellagotchi
RestrictAddressFamilies=AF_UNIX
MemoryMax=64M
CPUQuota=5%

[Install]
WantedBy=default.target
```

Use `sd-notify` (`READY=1`, `WATCHDOG=1` pings, `STATUS=` line showing mood) via the `sd-notify` crate. Also honour `$LISTEN_FDS` socket activation as an optional path (`shellagotchi.socket`) so the daemon can start on first command — implement the plain service first, socket activation is a **stretch goal (Task 22)**.

### Task 22: systemd unit + `install` helper

**Files:** Create `systemd/shellagotchi.service`, `src/cmd/install.rs`

### Task 23: `clean` integration with the real `clean` command

**Objective:** Honour the user's requirement that the ordinary shell command `clean` also cleans the pet.

Two mechanisms, both shipped:

## Risks, Tradeoffs, Open Questions

| Risk | Mitigation |
|---|---|
| **Hook breaks the user's shell** (clobbers `$?`, slows the prompt, spams job-control messages) | Highest-priority tests (Task 21); synchronous feed with a hard 5 ms budget by default; `SHELLAGOTCHI_DISABLE=1` escape hatch; the `prompt` path never does IPC |
| Prompt latency creeps up | `hyperfine` gate in CI; cache file only |
| Privacy — logging what the user types | Only `argv0` leaves the shell by default; `config.record_argv0 = false` disables even that; never store full command lines or cwd (only a salted hash) |
| Gorging via loops/scripts | Per-minute feed rate limit; consider also ignoring non-interactive shells (`[[ $- == *i* ]]` guard in the hook) |
| Laptop suspend → dead pet | `max_offline` cap with night simulation (Task 12) |
| Socket path when `XDG_RUNTIME_DIR` is unset (cron, ssh without a session) | Fall back to `/tmp/shellagotchi-$UID/` with mode 0700; `doctor` reports which path is in use |
| Multiple terminals racing feeds | Daemon is the single writer; the socket serialises; state mutation is behind one `Mutex` |
| Scope creep (evolutions, minigames, multiplayer) | v1 freeze: the feature list in this doc only. Everything else goes in `IDEAS.md` |

## Decisions (resolved with Pierre, 2026-07-27)

1. **Language:** Rust — confirmed.
2. **Death handling:** `grave` + manual `hatch` — confirmed as default.
3. **Failure framing:** switched to "bad food" — failures raise satiety more than successes but accumulate a `bad_food_meter` that risks sickness (health loss), rather than a flat happiness penalty per failure. See "Feeding rules" above.
4. **Species:** multiple species (`blob`, `cat`, `dragon`, `ghost`), picked uniformly at random at `hatch`; `--species` flag can force one. Purely cosmetic in v1 — no stat differences.
5. **Poop trigger:** commands-eaten only (every 40 fed/counted commands), time component removed entirely.

No open questions remain — plan is ready to execute.
